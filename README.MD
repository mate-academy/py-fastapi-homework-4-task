## Функціональність

### **Налаштування бази даних**
- **PostgreSQL для розробки**: застосунок використовує PostgreSQL як основну базу даних у середовищі розробки, налаштовану через Docker Compose.
- **SQLite для тестування**: легка база даних SQLite використовується для тестування, забезпечуючи швидке та ізольоване виконання тестів.

### **Наповнення даними**
- База даних може бути автоматично заповнена даними про фільми з наданого датасету. Включає пов'язані сутності: жанри, акторів, мови та країни, забезпечуючи багату та взаємопов'язану структуру даних.

### **Інтеграція з Docker**
- Проєкт повністю докеризовано, що забезпечує зручне налаштування та запуск застосунку і його залежностей.
- Docker Compose спрощує оркестрацію сервісів: FastAPI-застосунок, база даних PostgreSQL та інші необхідні компоненти.
- **MailHog для тестування email**: проєкт включає **MailHog**, який перехоплює вихідні листи та надає веб-інтерфейс для їх перегляду. Корисний для тестування реєстрації, скидання пароля та активації акаунту.
- **MinIO для об'єктного сховища**: проєкт інтегрує **MinIO** — S3-сумісне сховище для обробки завантажень файлів, наприклад аватарів користувачів.
- **Окремі файли Docker Compose**:
  - `docker-compose.yml`: основна конфігурація для розробки, включає FastAPI, PostgreSQL, MailHog та MinIO.
  - `docker-compose-test.yml`: окрема конфігурація, оптимізована для **наскрізного (E2E) тестування**, використовує SQLite як тестову базу даних.

### **Структура проєкту**
Надається добре організована та модульна структура проєкту, яка включає:
- **Моделі бази даних** та схеми для фільмів та пов'язаних сутностей.
- **Логіку маршрутизації** для управління API-ендпоінтами.
- **Допоміжні скрипти** для задач на кшталт наповнення даними та міграцій бази даних.
- **Фреймворк тестування**, інтегрований з `pytest`, включаючи модульні та E2E-тести для функціональності API.

Це забезпечує масштабований, підтримуваний та тестований API, що відповідає найкращим практикам веб-розробки.

## **Використання `get_db` для ін'єкції залежності бази даних**

Функція `get_db` — це генератор, що надає сесію SQLAlchemy для взаємодії з базою даних. Це забезпечує правильне управління сесією: сесія створюється до виконання маршруту та автоматично закривається після.

### **Приклад використання**
```python
from fastapi import Depends, APIRouter
from sqlalchemy.ext.asyncio import AsyncSession
from database import get_db  # Імпортуємо генератор get_db

router = APIRouter()

@router.get("/example")
async def example_route(db: AsyncSession = Depends(get_db)):
    """Використовуємо сесію db тут для взаємодії з базою даних"""
    pass
```

### **Ключові переваги**
- Спрощує ін'єкцію залежностей в обробники маршрутів.
- Забезпечує управління життєвим циклом сесії (створення та очищення).
- Покращує тестованість завдяки відокремленню логіки бази даних від обробника маршруту.
- Може використовуватись у кількох маршрутах для узгодженості.

## **Розширена ін'єкція залежностей у FastAPI**
Окрім ін'єкції бази даних, проєкт також включає залежності для **управління налаштуваннями, JWT-автентифікації, email-сповіщень та S3-сховища**.

### **`get_settings`: завантаження налаштувань проєкту залежно від середовища**
```python
import os
from fastapi import Depends
from config.settings import TestingSettings, Settings, BaseAppSettings

def get_settings() -> BaseAppSettings:
    environment = os.getenv("ENVIRONMENT", "developing")
    if environment == "testing":
        return TestingSettings()
    return Settings()
```
- Визначає, чи працює застосунок у режимі **розробки** чи **тестування**.
- Надає доступ до відповідних налаштувань конфігурації.

### **`get_jwt_auth_manager`: управління JWT-автентифікацією**
```python
from security.interfaces import JWTAuthManagerInterface
from security.token_manager import JWTAuthManager
from config.settings import BaseAppSettings

def get_jwt_auth_manager(
    settings: BaseAppSettings = Depends(get_settings)
) -> JWTAuthManagerInterface:
    return JWTAuthManager(
        secret_key_access=settings.SECRET_KEY_ACCESS,
        secret_key_refresh=settings.SECRET_KEY_REFRESH,
        algorithm=settings.JWT_SIGNING_ALGORITHM,
    )
```

### **`get_accounts_email_notificator`: налаштування email-сповіщень**

def get_accounts_email_notificator(

### **`get_token`: витягання та валідація JWT-токена**
```python
from fastapi import Header, HTTPException

async def get_token(authorization: str = Header(None)) -> str:
    if not authorization:
        raise HTTPException(status_code=401, detail="Authorization header is missing")
    
    parts = authorization.split(" ")
    if len(parts) != 2 or parts[0].lower() != "bearer":
        raise HTTPException(
            status_code=401,
            detail="Invalid Authorization header format. Expected 'Bearer <token>'"
        )
    return parts[1]
```
- Витягує JWT-токен з заголовка `Authorization`.
- Перевіряє правильність формату `Bearer <token>`.

#### **2. UserModel**

## Завдання: реалізація email-сповіщень для реєстрації та скидання пароля

Для покращення функціональності **управління акаунтом користувача** вам потрібно **інтегрувати email-сповіщення** для ключових дій користувача. Це передбачає модифікацію наступних контролерів:

1. **Реєстрація користувача (`register_user`)**
2. **Активація акаунту (`activate_account`)**
3. **Запит на скидання пароля (`request_password_reset_token`)**
4. **Завершення скидання пароля (`reset_password`)**

### **Використання класу `EmailSender` для сповіщень**
- Проєкт вже включає утиліту для відправки email: **`EmailSender`**.
- Ви будете використовувати наявну функцію ін'єкції залежностей:

  ```python
  def get_accounts_email_notificator(settings: BaseAppSettings = Depends(get_settings)) -> EmailSenderInterface:
      return EmailSender(...)
  ```

  Ця функція надає екземпляр `EmailSenderInterface`, відповідального за відправку різних типів листів, пов'язаних з акаунтом.

### **Необхідні зміни**
- У кожному з чотирьох згаданих контролерів вам потрібно **додати email-сповіщення** за допомогою екземпляра `EmailSender`.
- **Фонові задачі** (`BackgroundTasks`) мають використовуватися для асинхронної відправки листів без блокування основного запиту.

### **Як використовувати фонові задачі для відправки email**
- Вам потрібно згенерувати валідний **URL** для дії в листі (наприклад, сторінка входу, підтвердження скидання пароля).
- Приклад відправки листа про завершення скидання пароля:

  ```python
  login_link = "http://127.0.0.1/accounts/login/"

  background_tasks.add_task(
      email_sender.send_password_reset_complete_email,
      str(data.email),
      login_link
  )
  ```

  - Метод `background_tasks.add_task(...)` планує відправку листа у фоновому режимі.
  - Функція `send_password_reset_complete_email` виконується асинхронно.
  - Email одержувача та необхідне посилання передаються як аргументи.

### **Наступні кроки**
- Модифікуйте контролери (`register_user`, `activate_account`, `request_password_reset_token`, `reset_password`) для включення **логіки email-сповіщень**.
- Переконайтеся, що для дій на кшталт активації та скидання пароля генеруються **валідні URL**.
- Використовуйте **фонові задачі** для ефективної відправки листів.

Ця реалізація покращить досвід користувача завдяки автоматичним email-сповіщенням для критичних операцій, пов'язаних з акаунтом.

## Завдання: реалізація створення профілю та схеми валідації

Наступний крок у розширенні **кінотеатрального застосунку** — реалізація функціональності для **створення профілів користувачів**. Це включає визначення необхідної схеми валідації (`schemas/profiles.py`) та реалізацію маршруту (`routes/profiles.py`) для обробки створення профілю.

## **1. Схема профілю (`schemas/profiles.py`)**
**Схема профілю** визначає структуру запиту та відповіді профілю користувача. Вона має включати правила валідації для забезпечення коректності вхідних даних користувача.

### **Вимоги до схеми**
- **Валідація має виконуватися** за допомогою функцій з пакету `validation`:
  ```python
  from validation import (
      validate_name,
      validate_image,
      validate_gender,
      validate_birth_date
  )
  ```
- Схема має дозволяти користувачам надсилати:
  - **Ім'я** (`first_name`) та **Прізвище** (`last_name`) → мають містити лише літери англійської мови.
  - **Стать** (`gender`) → має бути допустимим значенням статі.
  - **Дата народження** (`date_of_birth`) → має бути валідною датою, і користувач має бути старше **18 років**.
  - **Інформація** (`info`) → не може бути порожньою або складатися лише з пробілів.
  - **Аватар** (`avatar`) → має бути валідним файлом зображення (`JPG, JPEG, PNG`) і не перевищувати **1MB**.

### **Приклад валідного запиту**
```json
{
  "first_name": "John",
  "last_name": "Doe",
  "gender": "man",
  "date_of_birth": "1990-01-01",
  "info": "This is a test profile.",
  "avatar": "<binary-image-data>"
}
```

## **2. Ендпоінт створення профілю (`routes/profiles.py`)**
Ендпоінт `POST /users/{user_id}/profile/` відповідає за обробку **створення профілю користувача**.

### **Деталі ендпоінта**
- **HTTP-метод**: `POST`
- **Шлях**: `/users/{user_id}/profile/`
- **Відповідь**: `ProfileResponseSchema`
- **Авторизація**: потребує валідного токена `Bearer` у заголовку `Authorization`.

---

## **3. Поведінка ендпоінта та обробка помилок**

### **1️⃣ Валідація токена**
Запит має містити **валідний токен автентифікації** (`Bearer <token>`).

- **Якщо токен відсутній**, поверніть:
  ```json
  {
    "detail": "Authorization header is missing"
  }
  ```
  - **Код помилки**: `401 Unauthorized`

- **Якщо токен має невалідний формат**, поверніть:
  ```json
  {
    "detail": "Invalid Authorization header format. Expected 'Bearer <token>'"
  }
  ```
  - **Код помилки**: `401 Unauthorized`

- **Якщо токен прострочений**, поверніть:
  ```json
  {
    "detail": "Token has expired."
  }
  ```
  - **Код помилки**: `401 Unauthorized`

---

### **2️⃣ Правила авторизації**
- **Користувач може створити лише власний профіль**, якщо він не має підвищених прав (наприклад, **admin**).
- Якщо **звичайний користувач** намагається створити профіль для іншого користувача, поверніть:
  ```json
  {
    "detail": "You don't have permission to edit this profile."
  }
  ```
  - **Код помилки**: `403 Forbidden`

---

### **3️⃣ Існування та статус користувача**
- Система перевіряє, чи вказаний `user_id` **існує** та чи є користувач **активним**.
- Якщо користувач **не існує** або **не активний**, поверніть:
  ```json
  {
    "detail": "User not found or not active."
  }
  ```
  - **Код помилки**: `401 Unauthorized`

---

### **4️⃣ Перевірка наявності профілю**
- Якщо у користувача **вже є профіль**, поверніть:
  ```json
  {
    "detail": "User already has a profile."
  }
  ```
  - **Код помилки**: `400 Bad Request`

---

### **5️⃣ Завантаження аватара до S3-сховища**
- Зображення аватара **завантажується** за допомогою:
  ```python
  s3_client: S3StorageInterface = Depends(get_s3_storage_client)
  ```
- Якщо завантаження **не вдалося**, поверніть:
  ```json
  {
    "detail": "Failed to upload avatar. Please try again later."
  }
  ```
  - **Код помилки**: `500 Internal Server Error`

---

### **6️⃣ Створення та збереження профілю**
- Профіль зберігається в базі даних після проходження всіх валідацій.
- Фінальний **URL аватара** генерується та включається у відповідь.

### **Приклад успішної відповіді**
```json
{
  "id": 1,
  "user_id": 1,
  "first_name": "john",
  "last_name": "doe",
  "gender": "man",
  "date_of_birth": "1990-01-01",
  "info": "This is a test profile.",
  "avatar": "http://minio-theater/avatars/1_avatar.jpg"
}
```
- **Код статусу**: `201 Created`

- Виявити граничні випадки та правильно обробити помилки.
- Переконатися, що ваша реалізація відповідає вимогам проєкту.

### **Запуск тестів**

#### **1️⃣ Запуск модульних та інтеграційних тестів (без Docker)**
Ви можете запускати модульні та інтеграційні тести **безпосередньо** за допомогою `pytest`:

```bash
pytest src/tests/test_integration/
```
Це виконає **лише інтеграційні тести**, забезпечуючи коректну роботу логіки вашого API **без запуску Docker-контейнерів**.

#### **2️⃣ Запуск наскрізних (E2E) тестів**
Для запуску повного **набору E2E-тестів** вам потрібно запустити тестове середовище за допомогою Docker:

```bash
docker-compose -f docker-compose-tests.yml up --build
```
Це підніме всі необхідні сервіси (база даних, MinIO, MailHog, екземпляр FastAPI) та виконає **наскрізні тести** всередині тестового контейнера.

### **Результати тестів**
- Логи тестів **виділять будь-які збої** та розбіжності між вашою реалізацією та очікуваною поведінкою.
- Використовуйте повідомлення про помилки з виводу тестів для **виправлення проблем та коригування коду**.

Дотримуючись цих кроків, ви можете переконатися, що ваша реалізація є правильною та повністю відповідає вимогам проєкту **Movie Theater API**.
